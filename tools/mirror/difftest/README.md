# tools/mirror/difftest — behavioral diff harness

Proves the P2 rewriter is **behavior-preserving**: the transformed (mirror) code
must produce the same observable output as the untransformed (oracle) code. The
mirror is generated by running the actual rewriter (`passes.apply_pointer_rules`),
so this tests the pipeline, not a hand-written copy.

```sh
python3 tools/mirror/difftest/run.py            # all cases
python3 tools/mirror/difftest/run.py tri_cursor # one case
```

## How the oracle stays "the 32-bit truth" without a 32-bit toolchain

Both binaries build 64-bit. The **oracle** is compiled with
`-DDIFFTEST_ORACLE_LOWMEM`, which makes `mmAlloc` return low-4 GB memory
(`mmap MAP_32BIT`); its pointer-in-`int` truncation is then lossless, so it
behaves exactly as the real 32-bit build would — the ground truth. The **mirror**
(rewritten to `uintptr_t`) uses a normal high-address heap and must still match.

On a machine with a real 32-bit toolchain, build the oracle with `-m32` and drop
`-DDIFFTEST_ORACLE_LOWMEM` instead; the harness result is the same.

## Negative control

Each case also builds the oracle **without** the low-memory crutch. If that
diverges or crashes, the hazard the rewriter fixes is real, so the PASS is
meaningful. (If the OS happens to hand out a low address, the control is reported
inconclusive rather than failed.)

## Two case kinds

**Synthetic** (`case.c` + `rules.toml`): a self-contained unit written to exercise
specific hazards. Good for pinning down one transform in isolation. Example:
`tri_cursor`.

**Real-TU extraction** (`extract.toml` + `shim.h` + `driver.c`): pulls verbatim
line ranges out of an actual `decomp/` source for the oracle, and the same ranges
out of the P2 rewriter's transform of that file for the mirror. Rules come from the
real manifest (`mirror/rules/`), so it validates the shipping rules against real
decomp bytes. The `shim.h` supplies only the handful of types/macros the extracted
function needs — not the TU's whole header web — and `driver.c` calls it and prints
a canonical (address-free) result. Examples: `track_init` extracts
`trackInitCollisionBuffers` from `track_dolphin.c`; `render_packed` extracts
`modelRenderInterpolateRootTransform` and its packed-address helpers from
`render.c` and drives two synthetic animations that together exercise both
bitstream refill paths; `drawbox_str` extracts `gameTextDrawBox` and passes a
subtitle string through its id-or-pointer `boxId` parameter; `objrender_staff`
extracts `objRender`'s staff-child walk (pointer-size stride).

`extract.toml` fields: `source` (repo-relative TU), `rules` (rules dir, default
`mirror/rules`), and `ranges` (list of inclusive `[start, end]` line ranges).
A case spanning several TUs uses `[[part]]` tables instead (each with its own
`source` + `ranges`), concatenated in order — callee before caller. Every part must
be touched by the rules.

`player_render` is the cross-TU case: `objRender` (objprint.c, hand rules) calls
`playerRender((int)obj, ...)` (player.c, the player DLL, generated whole-program
rules). It drives three frames through the player's carried object (raw-offset
pokes via `(char*)(int)heldObj` and its `VEHICLE_INTERFACE` render), the
Krazoa-spirit shader latched into and cleared through the `int` global
`gPlayerHeldObject`, the FX paths, a staff child, and a DLL object's interface
render. It caught a rewriter bug on its first run: two `occurrence=` rules on one
line were applied lowest-first, so the second never matched and a `(int)heldObj`
cast stayed narrow (fixed in `passes._by_occurrence`; unmatched TU rules are now a
build error).

Mirror builds define `DIFFTEST_MIRROR`, for shims that must mirror a rule applied
outside the extracted ranges (e.g. a widened global's declaration).
Line numbers into a frozen vendored decomp are stable; if a re-vendor moves them,
update the ranges (the harness fails loudly if the extracted mirror equals the
oracle, i.e. the rules stopped touching the extracted code).

### When the oracle needs the 32-bit *layout*, not just a low heap
The low-heap trick only makes pointer→int truncation lossless. It doesn't make
pointer *fields* 4 bytes wide. When the hazard is a pointer-size stride (e.g.
`walk += 4` over `childObjs[]`), the oracle's shim must give the walked array
the GameCube layout (`u32` slots under `DIFFTEST_ORACLE_LOWMEM`) while the mirror
uses native pointer slots. See `objrender_staff/shim.h` (`GuestPtr`). Removing the
`[[pointer.stride]]` rule makes that case's mirror segfault, which proves the
rule is load-bearing.

## Optional per-case build config (`case.toml`)

A synthetic case may add `case.toml` with:
- `link`    — extra `.c` sources to compile in (e.g. the mirror runtime).
- `include` — extra `-I` dirs.
- `oracle_defs` — extra `-D` macros for the oracle build only.

The `os_globals` case uses this: the oracle defines `DIFFTEST_MAP_MEM1` (maps a
page at `0x80000000` and populates the OS globals, like the 32-bit port) and reads
the absolute address; the mirror links `mirror/runtime/stairfax_os.c` and calls the
accessor. Both yield `tpms=40500`; the negative control (no map) faults. This is a
true differential test of an absolute-address → accessor rewrite.

## Adding a synthetic case

Create `cases/<name>/` with:
- `case.c` — decomp-style code with the hazards, a `run_case()` that prints a
  canonical result, and a `main()` behind `#ifdef DIFFTEST_MAIN`.
- `rules.toml` — the `[[pointer.*]]` rules to transform it (same schema as
  `mirror/rules/pointers.toml`); `file=` is the case source's repo-relative path.

Build output lands in `mirror/difftest-build/` (gitignored).

## Scope

Validates pointer-width transforms on compilable units — synthetic cases and
real-TU function extractions (via `shim.h`). Whole-TU compilation of an engine
source still needs the full header/HAL surface; that is the same milestone as a
compilable mirror build target (see `docs/adr/0001-native-64bit-portable-mirror.md`).
Extraction lets us diff real decomp behavior one function at a time until that
target exists.
